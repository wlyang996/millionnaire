## 收集一次失败

1. 在微信开发者工具或真机调试的 Console 中筛选 `MN-NET`，清空旧日志，重新点击登录一次。
2. 保留从 `login.mode` / `login.step.start` 到最后一个失败事件的完整日志。启动资源加载失败时，同时保留之前的 `http.fail`。
3. 在微信云托管后台运行日志里筛选 `MN-NET`，用客户端的 `trace` 值查对应请求。HTTP 编号以 `http-` 开头；WebSocket 编号以 `ws-` 开头。
4. 排查时提供这段客户端日志及同一时间、同一 `trace` 的后台日志即可。

## 如何判断断在哪一段

- `login.mode`：`wechatRuntime=false` 表示当前不是微信小游戏运行环境；微信环境下 `wechatEnabled=false` 表示后台未开放微信登录，当前会选测试登录。
- `wx.login.start/end/fail`：微信端获取临时登录凭证是否成功；失败保留微信的 `errMsg`。成功只记录是否拿到凭证，不输出凭证本身。
- `http.start/end/fail`：包含请求地址（无查询参数）、实际传输方式、耗时、HTTP 状态、服务端错误码及微信错误码。`url not in domain list`、超时等平台失败原因保留。
- 后台 `http.start`：确认请求确实到达应用。客户端有 `http.fail` 而后台找不到同一 `trace`，优先排查客户端到应用之间的连接，不能据此直接断言某个具体原因。
- 后台 `wechat.config`：启动时记录 AppID / AppSecret 是否已配置，只记录布尔值。
- 后台 `wechat.exchange.*`、`wechat.http.*`：确认后台是否发起 `jscode2session`、HTTP 状态、微信错误码、耗时及最深层异常类型；原有协议回退发生时记录 `wechat.http.fallback`。
- `login.wechat.profile-required`：新用户需要昵称，是正常流程，不是网络错误。
- `ws.start/open/hello`：分别表示开始连接、传输连接打开、服务端身份认证成功；`ws.open` 不能代替 `ws.hello`。
- `ws.error/close/retry/result.rejected`：记录连接失败、关闭码、关闭原因、重连等待时间及服务端拒绝码。后台对应 `ws.handshake/open/hello/auth.rejected/transport.fail/close`。
- `login.step.end` 的“建立连接”表示调用连接方法返回，最终连接结果仍以 `ws.open` 和 `ws.hello` 为准。

## 信息边界与验证

应用新增日志不输出昵称、请求/响应正文、Authorization 头、登录 code、令牌、OpenID、session_key 或 AppSecret。网络异常中的 URL 删除查询参数和用户密码，常见密钥字段会脱敏；后台异常仅打印类型，不打印可能带密钥 URL 或响应正文的异常堆栈。心跳与普通棋盘更新不逐条写诊断日志。

第三方 SDK、开发者工具或云平台本身生成的原始日志不在此脱敏范围内。提交排查材料前可只复制 `[MN-NET]` 行。
