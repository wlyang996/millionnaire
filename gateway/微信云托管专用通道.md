# 微信云托管专用通道

日期：2026-10-18。

## 原因与范围

用户实际日志报 `request:fail url not in domain list`；微信公众平台又明确拒绝把当前 `run.wxcloudrun.com` 默认域名配置成正式合法域名。用户已选择将微信端改为云托管专用通信。保留后台现有接口与鉴权，不调整玩法、移动速度或房间重连间隔。

- 微信小游戏：`wx.cloud.init` 一次初始化；业务 HTTP 用 `wx.cloud.callContainer`，业务长连接用 `wx.cloud.connectContainer`。
- 浏览器/H5：继续使用 XHR/fetch 和 WebSocket，支持现有本地后台覆盖地址。
- 仅将当前后台地址的业务接口路由至云托管；其他来源的资源 URL 保持原有加载方式。
- 云能力不可用、环境配置不合法、初始化或调用失败时明确报错并记录日志，不自动退回被拦截的业务公网域名。

## 当前部署参数

客户端 `assets/scripts/net/Config.ts` 的 `DEFAULT_WECHAT_CLOUD`：

```typescript
{ env: 'prod-d6gztvk354abc40f5', service: 'springboot-ad5i' }
```

参数依据已有 prod 服务域名及此前控制台信息填写，尚未实时核对控制台。环境 ID 应为环境标识，不能填存储桶名 `7072-...-1501212143`；服务名为服务列表中的名称，不能填完整服务域名。

其他部署可在首次业务请求前设置：

```javascript
globalThis.__MN_WECHAT_CLOUD = { env: '实际环境ID', service: '实际服务名' };
```

该配置包含公开部署标识，不包含 AppSecret 或长期密钥。当前实现用于小游戏已关联的同环境访问；尚未接入跨主体或共享资源方的 `new wx.cloud.Cloud({resourceAppid, resourceEnv})` 模式。

## 控制台前置条件

1. 微信开发者工具中的小游戏 AppID 必须关联/获准访问上述云托管环境；若环境属于其他账号，先核对资源关联或共享方式。
2. 服务名称、环境 ID 必须与代码一致，服务已部署且可用。
3. 基础库需要提供 `wx.cloud.init`、`callContainer` 和 `connectContainer`。缺少时会报 `WX_CLOUD_UNAVAILABLE`；不通过关闭域名校验绕过。
4. 后台微信身份认证仍需要此前的 `WECHAT_APPID` / `WECHAT_APPSECRET`。换通道不会取消或替代账号认证。

本次不操作线上环境、不关闭公网访问；H5 和管理后台仍需要当前访问入口。

## 协议与连接行为

- HTTP 保留原始方法、路径/查询参数、JSON 数据、Bearer 令牌和 `X-MN-Trace-Id`；云路由使用 `config.env` 和 `X-WX-SERVICE`。
- 云 SDK 返回的 HTTP 错误状态仍交给原业务逻辑处理。没有记录请求/响应正文或令牌。
- `connectContainer` 创建任务后，把 SocketTask 的 open/message/error/close 接到现有 GameClient，收到 `onOpen` 才视为连接打开，收到 `HELLO` 才表示服务端认证成功。
- 异步连接期间取消，迟到的 SocketTask 会关闭；错误或关闭仅结算一次，避免重复重连。
- 断线后沿用原有退避与 requestId 重发，保证服务端幂等；登录账号与身份不变。
- 云 HTTP 和建立长连接的 SDK 超时参数均为 10 秒，业务操作时限与人物移动速度没有改变。

## 更新后验收

重新构建/导入 `client/build/wechatgame`，Console 筛选 `MN-NET`：

1. `cloud.init.start` / `cloud.init.end` 显示当前 env、service。
2. `http.start` 的 `transport` 应为 `wx.cloud.callContainer`。
3. `ws.start` 的 `transport` 应为 `wx.cloud.connectContainer`。
4. 登录后出现 `ws.open`、`ws.hello`；实际建房、准备、投骰验证服务转发与长连接。
5. 若仍有失败，提供同次 `trace` 的客户端和云托管日志，不再反复添加默认公网域名。
