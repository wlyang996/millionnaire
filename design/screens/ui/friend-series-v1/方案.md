# 好友系列赛方案 v1

2026-10-10。状态：用户已批准33号布局与规则，系列赛已接入引擎、网关、数据库、管理后台与Cocos客户端。前置功能奖励、城市事件、称号已提交`f116add`。实现与验证见[实施记录](../../records/friend-series-implementation-2026-10-10.md)。

## 玩家流程

房主在首局开始前选择普通单局或系列赛，并选择后台允许的局数。全员可见计分规则后准备；开始首局时固定成员、规则版本、地图、初始资金、局时、投骰时限与快速模式。系列中途不能改规则。

每局仍玩完整的现有游戏，奖励、城市事件、租金递增与称号照常按该局规则运行。本局结算先显示净资产排名，再展示本局增加的系列积分和累计积分。回房间准备下一局时保留系列积分，资产、现金、手牌、位置、监狱、收入指标与城市事件全部重新开局。

计划局数完成后显示系列总榜与冠军，回到原房间；可开始新的单局或新系列，每次新系列有独立ID。系列积分不兑换游戏现金，称号也不额外发钱。

## 初始提案（审阅后实现，数值全部可配）

- 可选3、5、7局，默认3局；范围2～20局。普通单局仍为默认模式，后台开关控制是否开放系列选择。
- 名次积分示例：10、6、4、3、2、1、0、0，分别对应第1～8名。范围0～1000，必须随名次不递增。
- 同一局采用引擎的真实名次（包括1/1/3并列）。默认并列同分：两个第1名各拿第1名积分，第3名拿第3名积分。可另配“平分占用名次积分，向下取整”：两个并列第1名各拿floor((10+6)/2)=8分。
- 系列排名只按累计积分；同分并列，例如1/1/3，共同冠军。没有暗藏的净资产或胜场破同分规则。
- 真人与机器人均计分；允许机器人为独立后台开关，首局开始后不能新增或替换机器人/真人。观战者仅看榜单，不参与积分。
- 正常TIME_UP、LAST_SURVIVOR、NO_PLAYERS、ALL_AWAY都按真实结算结果计一局一次；管理中止/故障中止没有结果，不计分、不占已完成局数，保留积分等待重赛。部署会解散内存房间，不能承诺断点接着玩当前局。
- 首局前离开按普通房间处理；系列中的掉线不是退出，允许重连。局间主动退出保留已获积分、后续不再得分，不接受补位。玩家不足下一局最少人数时暂停系列，房主可结束并保留已完成总榜；没有自动给缺席者现金或补偿分。
- 所有人仍需准备下一局，延续既有准备机制，不自动开下一局、不另写固定“3秒后开局”。局间超时自动终止暂不增加，避免引入未确认的计时玩法。

UI只演示4人和3局，运行支持2～8人，30格最多4人、50格最多8人，沿用地图现有限制。4人示例第二局后总分16/16/8/6，本局增加6/10/4/3；第三局增加10/6/4/3后总分26/22/12/9，图中积分不会用金币符号。

## 实现方式

### 引擎

在`RuleConfig`新增`SeriesConfig`，包含enabled、局数选项/默认、rankPoints、并列计分方式、机器人开关、最少人数、正常终局原因白名单与中止处理策略；默认在RuleConfigs、范围在ConfigValidator。不会在Cocos再定义一套计分表。

在`SessionState`增加可空`SeriesState`：单调seriesNo、SETUP/BETWEEN_GAMES/PLAYING/FINISHED/ENDED状态、固定名册及展示快照、固定RoomSettings与config快照、计划局数、完成局列表、每人累计积分、已退出名单。旧构造与缺字段按无系列处理；单局路径行为不变。

新增经过权限检查的配置/结束系列命令与公开SeriesConfigured/Started/GameScored/Ended事件。首局StartGame验证固定名册并绑定规则；正常GameEnded以引擎已有GameResult生成一次计分事实；以`seriesNo + gameNo`去重，不在客户端或两个监听器各累加一次。中止GameAborted执行明确的重赛/暂停策略。离开、踢人、改设置、增加机器人在相应系列阶段拒绝或按退出规则处理。

新状态参与快照、回放、哈希与终局验证，旧引擎快照不跨版本恢复。SeriesView公开累计榜、完成局索引、每局分值、退出状态、下一局条件；随机与手牌保持私有。结算投影里区分本局净资产与系列积分。

### 网关、持久化与后台

GameSettings/SettingsMapper支持新配置、旧快照缺项关闭；client config下发局数和分值。建房选用绑定规则快照，后台后续发布不改在途系列。Vue管理页加编辑、并列示例与校验，构建static/admin一起提交。

RoomService/Wire/LiveRoom传新命令和SeriesView，公开积分由引擎事件驱动；同一房间原有串行输入机制保证重复WS、自动Tick、重连都不重复结算。新成员在系列启动后仅观战；机器人身份仍使用机器人头像。

当前迁移最新为V3，实现时重新确认版本后新增V4：保存系列表头、固定参与者与单局计分明细。唯一约束`room_id + series_no`和`series_id + game_no + user_id`；写入单局战绩和系列增分需同一事务或可幂等重试的事务入口。房间内存累计事实和异步落库均按同一个引擎计分事件，不从可删除公开日志重新计算。历史单局result_json无系列字段仍可读取。

个人战绩单局保留原排名，显示属于第几局/共几局和本局系列增分；系列详情独立读取已保存榜单，不让一场中止局伪造终局冠军。权限仅参赛用户和当前合法观战者可读。数据库MySQL5.7/H2兼容；用户注销与历史显示沿用当前隐私处理，不新增头像原图持久化。

### Cocos UI

沿用08好友房间、03本局结算、32称号页面与现有素材，不改用Vue做游戏。33号候选覆盖系列设置、局间积分、总榜三状态；首局启动后规则只读。4/8人列表可滚动，按钮为扁平圆角，详情隐藏棋盘，头像按真实参与者映射。

新增界面按用户确认后的33号布局接入。图中动态姓名、积分与局数由服务端下发；标题绶带、奖杯、人物、背景与按钮复用已有独立素材，整张候选图不当游戏页。退出与人数不足状态沿用现有确认框布局。实测4/8人名单、积分与总榜可滚动。复用的蓝绶带与候选木牌存在素材差异，未标记为逐像素还原。

2. 类型化配置、引擎系列状态和事件；至少覆盖2/4/8人、并列两种算法、机器人、正常/中止、退出、重连、重复结算、换规则拒绝、快照/回放。

4. Cocos设置、积分与结算联机真实显示；后台build、严格类型检查、单局回归、4/8人滚动和普通550ms移动。
5. 完整验证后提交。推送/部署另按用户明确要求执行；不因为UI稿完成就宣称系列赛已实现。
