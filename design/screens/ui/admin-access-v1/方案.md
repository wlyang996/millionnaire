# 管理后台账号、权限、会话与审计方案 v1

日期：2026-10-13。状态：设计建议，等待用户确认后开发。文档与交互草图不代表业务功能已实现或上线。延续已选定的“彩光游戏控制台”，演示账号、设备、时间和操作记录均为示意数据。

## 目标与范围

将现有共享管理员密码升级为独立后台账号，让每个人拥有明确权限，发布和回滚能追溯实际操作人。保留 Vue 3、Element Plus、Spring Boot 3.3.5、现有参数发布和版本冲突检查。

本轮设计包含账号登录、账号管理、三个固定角色、菜单与接口权限、会话撤销、操作审计。游戏玩家的微信登录、app_user 和玩家令牌独立保留。第一版不包含注册、短信、邮箱找回、多租户、自定义角色、逐字段授权或多人发布审批。

## 当前源码依据

- `gateway/.../config/AdminController.java`：登录只有 password；从 ADMIN_PASSWORD 读取共享密码；令牌在内存中，有效12小时；所有管理操作共用 check(auth)。发布与回滚的 created_by 固定为 admin。
- `web-manage/src/components/LoginPage.vue`：现有动画登录页只有管理员密码；`api.js` 在 sessionStorage 保存 Bearer 令牌；退出仅清除浏览器令牌。
- `CharacterController` 使用同一管理员检查。音频控制器也共用该检查，但音频功能目前属于独立的未提交工作，实施时根据其合入状态接入权限。
- 参数发布提交完整 GameSettings，公告属于同一快照。第一版不承诺“只能编辑公告”等局部权限，以免绕过页面后提交其他参数。
- 历史参数版本已经有 created_by；人物与音频现有历史结构不包含完整账号身份，需用新审计记录建立关联。

## 角色与权限边界

### 超级管理员 SUPER_ADMIN

可以查看、编辑、发布及回滚规则、人物和已接入的音频；可管理后台账号、撤销任意后台会话、查看审计日志。保护最后一个启用的超级管理员，禁止其被停用或降级；并发管理操作也必须遵守该约束。不能通过修改密码或角色绕过自己的身份校验。

### 运营管理员 OPERATOR

可以查看统计、全部规则和发布历史；可编辑、校验和发布规则及公告；可编辑人物草稿、上传、调整目录及发布；音频合入后按同样规则接入。不能回滚内容、管理账号、查看全局审计或撤销其他账号会话。

运营拥有完整配置快照的发布权；本方案不把它描述为单独的公告编辑权。页面发布摘要与 expectedActiveId 冲突检查继续生效。

### 只读观察员 VIEWER

可以查看统计、规则参数、生效人物目录和发布历史，比较历史规则版本。不能编辑、上传、校验草稿、发布、回滚或载入版本到编辑区；不能读取未发布素材与草稿。音频合入后仅可查看生效选曲及已发布试听。

三个角色均可查看自己的身份和权限、修改自己的密码、查看及撤销自己的会话。初次登录必须改密的账号只能访问身份、改密和退出接口。

### 权限实现

固定角色映射到明确权限键：dashboard:read、config:read/write/publish/rollback、character:read/draft/write/publish/rollback、audio:read/draft/write/publish/rollback、admin-user:manage、admin-session:manage、audit:read。

前端按服务端下发的 permissions 显示导航和按钮，后端统一校验全部 /admin-api/v1/** 请求。未登记权限的管理路由默认拒绝；新增接口必须声明权限。只读人物接口单独返回已发布目录及允许的版本元数据，不直接返回包含 packs 的原管理接口。公共客户端资源保持现有边界。

权限变更以服务端当前账号状态为准。降权后新请求立即按新权限处理；前端收到403刷新身份及导航，保留原有本地规则草稿但禁止提交，用户可复制必要内容。身份失效401清除令牌并回到登录，不把密码或令牌写入草稿。

## 页面布局与动效

新增“系统管理”导航组：后台账号、角色权限、操作审计，仅超级管理员可见。顶部增加当前姓名、角色和个人菜单；“我的会话”和“修改密码”属于个人菜单，任何角色都能进入。

### 登录页

复用四个几何角色和当前紫橙品牌。表单增加账号输入；输入账号时角色关注输入，输入密码时沿用遮眼动作；请求中、错误、成功状态继续与真实接口结果同步。账号或密码不正确统一提示；锁定时显示可重试时间。首次登录进入改密步骤，完成后再进入后台。

### 后台账号

主区为账号列表：账号、显示姓名、角色、启用/停用、最近登录；支持关键字和状态筛选、服务端分页。右侧抽屉完成创建、修改姓名及角色，用户名创建后不再修改。创建时生成临时密码，成功后仅显示一次；切页或关闭后不再次提供明文查看。

停用、角色变更及重置密码先展示对象和影响，再确认提交；成功响应后更新状态并播放短暂反馈。最后一个超级管理员的限制由前后端同时提示及执行；角色卡片显示当前角色可做的操作，避免只给一个名称。

### 角色权限

采用角色选择卡片和按业务模块展开的权限矩阵，显示查看、编辑、发布、回滚及系统管理能力。固定角色仅用于解释，第一版不提供可保存的自定义勾选框。个人菜单“我的权限”仅显示自己的角色能力。

### 我的会话

展示设备概要、创建时间、到期时间、近期活动与当前会话标记。本人可退出当前设备或撤销其他自己的会话；超级管理员在账号详情查看指定用户会话。撤销当前会话成功后回到登录。近期活动使用受控更新间隔写入，界面不声称是实时在线人数。

### 操作审计

主区显示时间、实际操作人、动作、对象、结果、请求编号；支持账号、动作、成功/失败和时间范围查询及分页。点击记录展开抽屉，显示允许公开的变更摘要、关联版本及拒绝原因。规则发布记录可跳转现有版本对比。日志页面不提供修改或删除入口。

### 动效规范

复用现有 motion-v、BorderBeam 和主题变量，角色选择沿用弹簧指示块；抽屉渐入、状态徽章过渡、会话撤销收起、日志详情展开。彩光集中在欢迎区、选中角色和成功反馈，列表正文与输入保持稳定。丰富/标准/简化偏好及系统减少动画继续生效，后台标签暂停装饰动画；触屏按钮有等价反馈。

## 登录与会话设计

保留 POST /admin-api/v1/auth/login 路径，请求改为 username + password；保留 token、expiresAt，并增加用户摘要、permissions、mustChangePassword。不保留共享密码登录旁路。

密码通过 Spring Security Crypto 的 PasswordEncoder 存储带算法标识的单向哈希；使用与当前 Spring Boot 依赖管理兼容的版本，不为本功能升级整个框架。推荐 BCrypt，成本参数先以目标容器测试后确定并通过配置调整；拒绝超过编码器字节长度限制的密码，不能静默截断。[官方密码存储说明](https://docs.spring.io/spring-security/reference/6.5/features/authentication/password-storage.html)。

建议密码至少12个字符、最多64个字符，另执行BCrypt的72字节上限校验，避免多字节字符超限；初始化、创建、重置和本人改密共用规则。使用统一AdminAuthService、限定管理路由的请求过滤器与处理方法权限声明：过滤器解析可信身份，处理方法统一检查权限，无声明则拒绝。密码编码复用spring-security-crypto，不改变游戏公开接口和WebSocket的现有认证。

继续采用随机不透明 Bearer 令牌；数据库只保存 SHA-256 摘要，不保存令牌明文。生产从数据库读取会话和当前账号状态，多实例共享撤销结果；不采用只在单实例内存缓存的权限判断。本地无数据库模式可用独立内存仓库，生产数据库故障时拒绝认证，不降级成共享密码。

会话采用绝对到期时间，建议默认沿用12小时；可并存多设备会话。退出、停用、重置密码和本人改密均撤销对应会话；改密成功后要求重新登录。修改角色同时撤销该用户已有会话，防止旧页面继续以旧权限操作。下一请求即生效；前端在页面恢复、执行操作或身份刷新时发现，第一版不承诺即时推送下线。

失败次数、锁定时长和登录速率限制作为服务端安全配置，沿用现有“5次 / 5分钟”作为候选默认值，改为按账号计数并结合来源限制。无效用户名使用等价密码校验路径与统一错误文案，避免泄露账号是否存在。只有配置的可信代理才能提供客户端IP，不直接信任任意转发头。

前端继续使用 sessionStorage 和同源 Bearer 请求，不使用自动附带身份的登录Cookie；禁止令牌出现在URL、日志、审计和分享状态。未来若改为Cookie登录，再同时设计相应CSRF保护。

## 数据和审计

新增 admin_user：稳定ID、规范化且唯一的不可变用户名、姓名、password_hash、role、status、must_change_password、失败次数与锁定截止时间、乐观版本、创建/更新时间与最近登录。

新增 admin_session：token_hash、user_id、创建/到期/撤销时间、最近活动时间、受限长度的设备概要及来源信息。索引支持按用户查询会话和清理过期会话。不会向客户端返回token_hash。

新增 admin_audit：稳定事件ID、真实actor_user_id、当时用户名/姓名快照、模块、动作、对象ID、结果、发生时间、request_id、脱敏变更摘要。旧历史“admin”保留为“历史共享管理员”，不冒充新账号的操作。

规则 created_by 改为来自可信身份的不可变用户名；不能接受请求体中的操作者字段。审计用稳定用户ID建立关联。人物、音频发布通过审计对象ID关联版本，查询时提供真实发布人；历史缺失身份则明确显示“未记录”。

管理成功写入与审计尽量共用数据库事务：账号变更、会话撤销、版本元数据提交须与成功审计一致；失败和越权另行记录，不因业务事务回滚丢失。COS上传属于外部操作，分别记录尝试/结果并与元数据关联，不宣称外部对象和数据库具有原子事务。

审计只记录白名单字段；密码、哈希、完整Authorization、完整上传文件及未脱敏请求体全部排除。角色、状态、发布/回滚目标和版本冲突允许记录。第一版不提供导出与自动删除，后续按实际保留策略配置归档。

为防止两个请求同时删除最后管理员，管理操作在事务内锁定统一保护记录，再验证启用超级管理员数量；不能只依赖页面检查。账号用户名唯一与乐观版本在数据库约束和请求校验中共同执行。

## 接口规划

- POST /auth/login；GET /auth/me；POST /auth/logout；POST /auth/password。
- GET /auth/sessions；POST /auth/sessions/{id}/revoke（服务端校验归属）。
- GET /users；POST /users；PATCH /users/{id}（姓名、角色、状态，携带expectedVersion）；POST /users/{id}/reset-password。
- GET /users/{id}/sessions；POST /users/{id}/sessions/revoke-all，超级管理员专用。
- GET /roles，返回固定角色说明与权限映射；GET /audit，返回分页审计。
- 路径均在 /admin-api/v1 下。账户失效401，权限不足403，版本冲突409；初次改密状态使用明确业务码并限制允许的路由。

现有规则/人物接口路径尽量保持，替换为统一身份与权限校验；客户端接口不纳入后台账号权限。账号、会话和审计响应不得泄露密码哈希或令牌摘要。

## 初始化与迁移

仅在账号表为空时，通过新环境变量 ADMIN_BOOTSTRAP_USERNAME、ADMIN_BOOTSTRAP_PASSWORD 创建第一位超级管理员，密码只存哈希，并强制首次改密。配置缺失时后台返回明确初始化未完成错误，游戏服务可继续运行。数据已有账号时环境变量不覆盖密码，也不恢复被停用账号。

部署前准备初始化变量，验证首次登录后移除初始化密码；旧ADMIN_PASSWORD不再作为登录凭证或后门。运维恢复流程单独提供受控CLI，要求显式选择目标及新密码，写审计并撤销会话，不设置公开重置接口。

只新建下一可用Flyway版本，实施时重新核对目录和合入状态。目前V6音频迁移在工作区，不能抢用或改写它；若该版本保留，则账号迁移从V7开始。兼容MySQL5.7与H2 MySQL模式，表选项使用 ${table_options}，禁止修改已执行脚本。

启用新认证后旧内存令牌全部失效，需要重新登录。数据库新增表保留；应用回退到共享密码版本会失去新权限约束，不能把普通代码回滚当作安全等价回退。

## 开发顺序与验收

1. 后端账号、密码、初始化、统一鉴权和数据库会话；新旧登录页同时改为账号+密码，先验证401/403及首次改密流程。
2. 固定角色贯穿规则、人物、已合入音频；前端可见性、只读界面和接口权限一同落地。
3. 账号列表、个人信息/密码、会话页面及管理员保护约束；验证多实例撤销与并发管理。
4. 操作审计、真实发布人及版本中心关联；数据库成功操作与审计一致性验证。
5. 动效、主题、手机布局与完整回归，完成后按用户既有约定提交源码和管理端静态产物并推送。

必测：各角色直接调用每类接口的允许/拒绝；只读不能读取草稿；停用/重置/降权后旧令牌失效；本人退出服务端撤销；匿名、过期与未登记接口失败；最后管理员并发保护；密码/令牌不进入审计；旧版本不伪造新操作者；已有发布摘要和409草稿保护不退化。

后台按约定先server/mvn install，再gateway/mvn test，执行全部Flyway的H2回归。前端执行npm test/build并提交static/admin。真实MySQL5.7、多实例、COS与生产发布单独验收，不能以本地结果代替。prod推送可能触发部署、解散对局；本轮仅方案文档，不新增迁移或业务代码。
