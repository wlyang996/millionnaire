# 事件情景卡 UI 候选 v1

日期：2026-10-19。状态：待用户审核，未接入客户端或后台。

用户同意先制作一张奖励、一张扣款的候选稿，确认布局后再补齐现有事件故事素材。此次只制作设计预览，不修改事件概率、金额、停留时长或客户端逻辑。

## 两张候选

- `奖励事件-拾金不昧-v1.png`：归还钱包、失主酬谢；绿色分类题头，金色 `+300 金币`，与善举情景对应。
- `扣款事件-违章停车-v1.png`：车辆、禁停标识、罚单；珊瑚红分类题头，红色 `−200 金币`，与扣款缘由对应。

两张沿用统一圆角金框、棋盘压暗背景、情景插画、理由与金额区域。保留自动收起机制，底部细进度条与“点击卡片可提前收起”用于表达可跳过展示；不新增确认、购买或支付操作。

金额、人物名和顶部余额均为设计示例，不代表默认玩法参数。最终接入时文字、金额、倒计时和进度由实时 UI 绘制；事件插画、卡框和装饰必须作为独立素材交付，禁止把整张候选图当作运行界面贴图或从整页截图裁素材。

## 已核对的现状

`client/assets/scripts/core/EventDraw.ts` 包含普通奖励 8 条、罚款 8 条故事。`screens/board/EventOverlay.ts` 当前按奖励、罚款类别复用通用插画，幸运/不幸还会覆盖为四叶草/乌云卡面。现有奖励和扣款金额都使用红色。当前故事文案主要在客户端按种子选取，不是后台完整的事件故事目录。

## 通过审核后的接入方向

以服务端稳定事件 ID 关联情景素材、标题和描述，不按文案关键字猜图。后台编辑故事、效果类型、插画、金额范围和权重并发布，旧房间沿用绑定版本。客户端使用同一事件结果绘制匹配的插画与金额；奖励和扣款同时通过文字、正负号和色彩区分。新增后台配置需要按项目约定同步 RuleConfig、GameSettings、SettingsMapper、校验器和管理页；此处仅描述实施方向，尚未开发。

先审这两张布局，再确定现有 16 条普通故事和幸运/不幸故事的独立插画范围。实现时沿用按需加载、有限并发和版本化对象存储，不恢复全量预热，不增加人物移动或掷骰子动画时长。
