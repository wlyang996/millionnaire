# 发布摘要统一与版本中心完善

日期：2026-10-13。用户授权继续完成发布摘要与版本中心两项。本次代码及管理端静态产物纳入本次提交，本地验证已完成，用户已授权推送prod，实际部署结果待确认。

## 发布摘要

- 发布窗口复用历史版本对比组件，按玩法分组展示变化项，可筛选；使用完整中文名称、开关状态、金币 / 秒 / 毫秒 / 轮次等单位。
- 权重变化导致其他项目占比改变时，显示“概率联动”及百分点变化。编辑区变更计数使用相同逻辑，与发布摘要一致。
- 创建独立的 JSON 草稿快照，摘要、确认时的校验、实际发布使用同一份内容和同一个 `expectedActiveId`。后续编辑不能改变已核对的快照。
- 将旧值标为“参考版本”，避免并发发布后仍把旧编辑基准误标为当前生效版本。
- 409 冲突保留编辑区草稿，并禁用原确认按钮。用户可点击“重新核对生效版本”：重新读取当前配置，列出整份草稿相对新版本的差异，再明确确认发布。该操作不默默更新编辑区或跳过差异核对。
- 返回编辑、取消窗口及发布失败均保留草稿；发布成功才重新加载生效配置。

## 版本中心

- 新增 `GET /admin-api/v1/config/history/page`，旧 `/config/history` 列表接口保持原有契约。鉴权仍使用现有管理员令牌。
- 支持分页、每页10 / 20 / 50条，以及版本号 / 发布说明 / 发布人关键字、发布类型、版本状态筛选。历史版本不再局限于最近50条；版本选择器支持远程搜索。
- 显示记录中的发布人、普通 / 回滚 / 内置默认类型、回滚来源及规则标识；增加“对比回滚来源”。来源为0时明确显示内置默认配置。
- `admin`、`system` 分别显示管理员、系统，搜索也支持这两个中文名称；其他发布人保留原记录值。没有新增多账号或权限体系。
- 分页只读取元数据，不为了浏览历史而解析全部规则快照。内存和数据库采用一致的筛选及默认配置计数规则；SQL参数绑定，LIKE中的百分号、下划线、感叹号按字面搜索。
- 刷新记录只更新版本中心的记录，不改写规则草稿或原发布基准。如果服务器已有新生效版本，页面明确提示，发布仍执行版本冲突校验。
- 无匹配结果、读取失败重试、快速查询响应防覆盖及手机控件换行均有对应处理。
