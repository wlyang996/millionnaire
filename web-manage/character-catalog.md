# 整套人物素材与 COS 配置

2026-10-12：后台入口 `/admin` →「人物素材」。功能上线后，管理员上传并发布图片即可更新新房间，不需要为每次换图重新打包客户端或后台。本次功能代码本身仍须部署一次。

## 一位人物包含哪些图片

每套固定七张 PNG：普通头像 `avatar`、棋盘棋子 `pawn`、资产等详情中的半身人物 `portrait`、援助递币 `give`、援助接币 `receive`、欠款忧虑 `worry`、冠军托杯 `celebrate`。七项齐全才能发布；不是只替换头像。

单张不超过 5MB，宽高各 64～2048 像素，宽高比 0.35～2。头像近似正方形（比例误差最多 5%），另外六张须有透明通道和至少 1% 全透明像素。建议头像 256～512 像素、人物 512～1024 像素，控制小游戏内存和下载量。每张只放一位人物；后台校验文件格式与透明度，人物内容仍需管理员预览确认。

编号 0～7 为已有八位人物，可整体替换；8 保留给机器人；新增人物自动分配 9～998，不通过取模映射成旧头像。排序、名称、启停可独立发布，保持原来的整套图片。停用隐藏新的选择项，已有账号存储的身份不变；更新资料时重新选择启用的人物。

## 存在哪里

图片实际存在腾讯云 COS 的私有桶，路径为 `characters/{人物ID}/{素材版本UUID}/{项目}-{SHA256}.png`。数据库保存图片路径、尺寸、校验值、草稿和人物目录版本，不保存图片二进制。后台 `resources` 只包含管理页构建文件和迁移脚本。

客户端图片地址由网关提供，如 `/api/characters/assets/{UUID}/avatar.png`。网关在微信云托管容器内取得临时凭证读取私有 COS，客户端不接触凭证或任意外部图片域名。该版本不需要另配图片访问域名或 COS 公网读权限；图片流量经过网关，暂未接 CDN。

## 微信云托管需要配置什么

1. 在微信云托管控制台「对象存储 → 存储配置」复制当前环境的存储桶与地域，不需要另开腾讯云账号或申请长期密钥。本项目用户提供的截图确认：`COS_BUCKET=7072-prod-d6gztvk354abc40f5-1501212143`、`COS_REGION=ap-shanghai`。它们仅为本环境配置值，不写死在源码中。
2. 在实际运行 Java 网关的服务环境变量中设置 `COS_BUCKET`、`COS_REGION`。原 `COS_SECRET_ID` / `COS_SECRET_KEY` 已不再读取，不要再申请或填写它们。后台通过 `http://api.weixin.qq.com/_/cos/getauth` 获取临时凭证并在到期前刷新；上传通过 `/_/cos/metaid/encode` 获取管理员文件元数据，写入 `x-cos-meta-fileid`。参考 [微信官方 COS-SDK 服务端说明](https://developers.weixin.qq.com/minigame/dev/wxcloudrun/src/development/storage/service/cos-sdk.html)。
3. 在微信云托管「云调用」中，为这个服务放行两个开放接口路径：`/_/cos/getauth`、`/_/cos/metaid/encode`。若控制台列出服务范围，选择实际运行网关的服务。无需放行删除文件或修改存储权限接口。这是平台权限配置，代码不能自行开通。
4. 沿用已有数据库设置：`SPRING_PROFILES_ACTIVE=db` 及 `MYSQL_*`。启动时 Flyway 执行新迁移 `V5__character_catalog.sql`；原 V1～V4 不修改。本次临时凭证改造不增加迁移。不启用数据库时，目录仅用于本机演示，重启丢失。
5. 按[后台账号说明](admin-access.md)初始化独立管理员账号（已有账号无需重建），部署本次代码后登录 `/admin` →「人物素材」，点击「检查临时凭证」。成功仅表示取得有效凭证，实际桶、地域和读写权限仍需上传素材并读取预览验证。两个变量齐全才启用上传；缺少云调用放行、接口拒绝、网络不通或响应过期会显示中文错误，不返回凭证内容。
6. 微信小游戏的图片下载沿用网关 HTTPS 域名，确保该域名在小游戏的下载合法域名中。H5 的图片与 API 也使用同一网关，不需要单独给 COS 配 CORS。存储安全域名和缓存配置无需为此修改。

临时凭证接口依赖云托管容器的开放接口服务，不能在普通本机环境直接验证。程序使用官方示例的 HTTP 内部访问方式，COS 对象上传/下载仍用 HTTPS；不会把长期密钥、临时密钥或 token 发给管理页，也不会将接口原始错误响应写入日志。刷新失败时不会退回旧凭证或长期密钥。服务保存配置/部署可能重启后台，应安排在没有进行中的对局时。

## 上传、发布与回滚

「新建人物」→填写名称、排序、备用人物→「创建整套草稿」→上传七张并查看预览→保存改动的资料→「发布完整七项素材」。上传本身不生效；发布时服务端重新读取七项校验，完整成功才原子切换目录。少一项、损坏、上传失败、并发版本变化都不会生效。慢速上传不阻塞正在进行的房间读取目录。

替换已有人物时，在目录选择「配置 / 替换整套」，创建该 ID 的新草稿，重新上传七项。已发布素材不可覆盖。只改名称、排序或启停，可选「仅发布名称、排序、启停」，无需重复上传图片。

历史可回滚为新的目录版本，旧图片保留。尚未做 COS 自动清理：失败/被并发拒绝的上传可能留下未引用对象；不要删除仍被历史目录或进行中的房间引用的对象。发布和回滚带生效版本校验，多人同时管理需刷新后再操作。

## 生效边界

新房间绑定创建时的人物目录版本，已有房间保持原版本，避免对局途中人物突然换图。进入旧房间的新增人物若该版本不包含该 ID，显示本地默认人物。资料页读取当前生效目录，超过八位时分页；更新后重新进入资料页/登录可拉取新目录，不持续轮询。

客户端按需一次加载一套七张，全部成功后同时接入头像、棋子、详情和组队姿态，失败时整套回退到配置的内置备用人物，不混用新旧人物。一次下载失败会在本次运行保留备用，重启客户端或发布新的图片版本后重试。

2026-10-13动作协议扩展：七项基础素材保持兼容，可追加pawncrouch（蓄力）、pawnairborne（腾空）、pawnland（落地）、pawnready（准备）。追加任意一张就必须补齐四张，且与pawn画布尺寸一致；预览中确保人物大小和脚底位置一致。完整十一张一起校验、发布、下载；任意一张失败整套回退。旧七张仍用静态棋子移动，动作速度沿用房间配置。后台支持逐帧查看和循环预览；下载姿态不混用其他人物。
