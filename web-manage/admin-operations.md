# 管理端运营扩展

日期：2026-10-16。沿用现有管理端布局和模块配色。功能入口位于「运营工具」和「系统管理 → 角色权限」。源码实现与本地验证不等于生产部署已生效。

## 玩家与对局查询

- 玩家查询：昵称包含查询或完整玩家 ID 精确查询；分页展示昵称、账号状态、创建与最近登录时间。详情包括记录局数、名次统计及最近20局。只读查询，不提供封禁、改名、资金修改或玩家身份模拟。
- 历史对局：按房间号/完整房间 ID、完整玩家 ID、结束时间范围检索，分页查看结算与公开事件时间线。事件每页50条；只读取公开事件，不读取聊天、微信身份、令牌或私有手牌。玩家明细被清理后，仍能查看保留的对局表头。
- 独立权限为 `player:read` 与 `game:read`，三个系统固定角色均包含。查看资料或详情写入管理审计。
- 无数据库时，仅展示当前进程保留的玩家和近期对局，页面明确提示；不把内存结果描述为全部历史或实时在线。

## 发布审批与预约

规则、音频和人物页面增加「提交审批 / 预约」。规则固定提交时的参数；音频须先保存草稿，固定草稿修订及设置；人物固定素材包、修订及基准目录版本。审批详情提供规则差异、音频试听和人物图片，素材预览使用提交时记录的引用。

审批是新增可选途径，原直接发布入口仍按原权限提供。状态为待审核、已批准、已发布、驳回、撤销和失败。提交人不能审核自己的审批单；审核人须具备 `release:approve`、该模块发布及草稿读取权限。超级管理员可审核；自定义角色也可组合相关权限。运营管理员可提交。

预约时间按浏览器当前时区输入，服务端保存 epoch 毫秒；留空表示批准后尽快执行。最多预约90天后。每10秒扫描到期任务，重启后继续扫描数据库中已批准的任务，不保证秒级准点。

执行时重新读取提交人和审核人的账号、强制改密状态与权限，并检查基准版本、草稿修订及固定内容。冲突或权限变化会进入失败状态，不覆盖其他人的新版本。失败单需核对后重新提交；没有自动重试发布。成功发布与审批完成、发布审计共享数据库事务，通过数据库管理锁避免跨实例重复执行。该能力不改变游戏房间自身的单实例约束。

`release:read` 只允许看到自己具有该模块发布及草稿读取权限的审批单；只读观察员不能读取审批草稿。

## 自定义角色

系统三个固定角色保留，不能编辑。新增角色标识为 `CUSTOM_` 开头的大写字母、数字或下划线，最长24位。支持名称、说明与模块权限组合，并可分配给后台账号。

编辑、发布等能力会自动补齐相应查看依赖。账号管理与其他用户会话管理保留给超级管理员，不能分配给自定义角色。修改角色使用版本校验，并撤销使用该角色的全部会话；重新登录读取新权限。新增角色允许无业务权限，本人会话、密码和权限页仍可访问。最后一个超级管理员保护继续有效。

仅有玩家、战绩或音频等权限的账号会进入首个可访问页面，不依赖规则配置权限。

## 素材引用、回收与清理

权限为 `media:manage`。库存覆盖当前目录可见上传以及本功能上线后登记的上传，不扫描整个 COS 桶，也不管理未知路径或内置素材。

引用保护覆盖所有人物草稿与不可变已发布素材包、全部音频历史、当前音频草稿以及待审核/待执行的音频审批。历史人物包不会删除，因此进行中房间引用的旧素材仍受保护。

未引用素材可移入回收站；音频从可选素材中隐藏，不改动生效配置。回收站期间文件仍保留，可恢复。至少7天后才可永久清理，并要求输入完整素材路径确认；清理前再次检查引用与版本。

永久清理先持久化「清理中」状态，再调用 COS，成功后标记已删除。失败或进程中断后可重新核对并重试；开始永久清理后不能再恢复，防止把已删除文件误显示为可恢复。清理结果记录审计。真实 COS 删除还须核对云托管临时凭证权限。

## 数据库与验证

- 新增 SQL 迁移 V8，创建自定义角色、审批单和素材登记表，使用 `${table_options}`；V1～V7保持不变。
- 新增 Flyway Java 迁移 V9：仅在 H2 下将战绩二进制摘要长度校验由 `LENGTH` 改为 `OCTET_LENGTH`，保留原约束其他部分。H2 2.x 的 `LENGTH` 会将摘要当作 UTF-8 字符，导致部分正常战绩被拒绝；MySQL 的 `LENGTH` 本来按字节计数，因此 V9 在 MySQL 上无 DDL。
- H2 MySQL 模式验证迁移、权限、审批、预约、版本冲突、撤销、引用保护、回收恢复和删除失败重试；真实 MySQL 5.7、COS 与生产发布不由这些测试替代。
- 本轮本机浏览器自动审批两次超时，尚未完成页面显示、交互和手机布局验收；前端编译与接口测试单独记录。
